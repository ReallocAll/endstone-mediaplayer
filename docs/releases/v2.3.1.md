## Endstone MediaPlayer v2.3.1

v2.3.1 restores physical-screen rendering and video playback state across
server restarts and Endstone plugin reloads.

### Fixes

- Restores persisted plugin-managed map screens when an eligible public viewer
  enters the same dimension within the 16-block viewing range. Existing map
  IDs are reused; incomplete persisted map identity is rejected without
  allocating replacement maps or modifying the world.
- Persists the active video's catalog name, frame, loop position, and explicit
  playing or paused state. Playing screens resume lazily when an eligible
  viewer arrives, while paused screens restore their saved frame without
  advancing. Stopped and finished screens remain stopped.
- Rebuilds MediaPlayer's online-player tracking from
  `Server::getOnlinePlayers()` during plugin enable. Players who remain online
  across `/reload` now trigger screen restoration without issuing another
  `/mpv` command.
- Keeps failed media or map restoration retryable instead of creating a
  partial session or permanently suppressing later recovery.

### SDK documentation

- Expands the C23 SDK guide with an in-process/main-thread quick start,
  create-or-find flow, pixel and stride contract, frame-transaction lifecycle,
  result reference, and troubleshooting guidance.
- Expands the Python binding guide with a complete Endstone `Plugin` example,
  screen CRUD and inspection reference, typed exception mapping, lifecycle
  rules, and common integration pitfalls.
- Replaces the minimal C and Python samples with create-or-find, pixel update,
  atomic frame, statistics, and cleanup examples that preserve visible output.

### Compatibility and operational notes

- The public C ABI remains `MP_API_V1`; the Python package version remains
  `0.1.0` under its independent version policy.
- Playback restoration resolves the saved catalog name against the current
  video directory. Missing, invalid, or dimension-mismatched media remains
  pending for a later safe retry.
- Logical screens still require `/mpv materialize <name>` before they have a
  physical map-wall output. Physical screens and MCV1 remain limited to 7×4
  tiles.

### Assets

- `endstone_mediaplayer-windows-x64.zip` — Windows x64 plugin DLL and matching PDB.
- `endstone_mediaplayer-linux-x64.tar.gz` — Linux x86-64 plugin shared object.
- `endstone_mediaplayer-sdk.zip` — C23 header, Python wheel, SDK documentation,
