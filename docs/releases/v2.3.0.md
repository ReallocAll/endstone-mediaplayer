## Endstone MediaPlayer v2.3.0

v2.3.0 expands MediaPlayer from fixed map-video playback into a general tiled display engine while preserving NBS music and MCV1 compatibility.

### Highlights

- Adds logical screens up to 1024×1024 tiles, backed by sparse resident tiles instead of a full-screen framebuffer.
- Adds the tiled Surface/Presenter pipeline with dirty-generation tracking, bounded pending work, viewer reach filtering, and incremental resend/stream budgets.
- Adds MPS1 static-image playback and a bounded-memory image converter for very large tiled images.
- Adds a stable single-header C23 API for finding, creating, querying, updating, clearing, renaming, and deleting screens, including atomic frame transactions.
- Adds the `endstone-mediaplayer` Python binding (version 0.1.0) with provider lifecycle/reload detection and native error mapping.
- Adds `/mpv materialize <screen>` for upgrading eligible API-created logical screens in place. The screen identity, runtime ID, API handle, Surface generation, and resident pixels are preserved.
- Materialization validates an exact physical backing rectangle, treats the player's feet Y as the bottom display row, applies busy guards, and rolls back map/item-frame/persistence failures.
- Retains MCV1 video and NBS soundtrack behavior, including pause, resume, looping, and synchronized stop semantics.

### Reliability and compatibility

- Validates stored CRCs for compressed MCV frames and supports UTF-8 MCV paths on Windows.
- Cleans up a video session when its initial frame cannot be decoded.
- Validates the public ABI header before copying the complete provider table in the Python loader.
- Reports public screen persistence failures transactionally instead of acknowledging mutations that were not saved.
- Keeps Windows ABI interop on the shared dynamic UCRT and supports Clang/clang-cl C23 builds on Windows and Linux.

### Limits and operational notes

- Logical size does not imply physical materialization: Minecraft map-backed screens and MCV1 remain limited to 7×4 tiles.
- Sparse storage avoids whole-screen allocation, but changed-tile bandwidth still scales with update rate and eligible viewers. Consumers should query capabilities/statistics and use bounded frame budgets.
- Materialization is a player/world command boundary; it is not exposed as a native SDK call.
- The separate live-capture plugin is not included in these core release assets.

### Assets

- `endstone_mediaplayer-windows-x64.zip` — Windows x64 plugin DLL and matching PDB.
- `endstone_mediaplayer-linux-x64.tar.gz` — Linux x86-64 plugin shared object.
- `endstone_mediaplayer-sdk.zip` — audited C23 header, Python wheel, SDK documentation, examples, and GPL-3.0 license.
